the scale of the problem
- 50 agents working in debt recovery.a
- Legacy Trust operates across personal loans, credit cards and auto finance.
- 100,000+ delinquent accounts (overdue on payment).
- Problems affect the whole debt recovery process.
- Both straightforward and complex cases currently go through agents.
- ~38% of cases are estimated to be straightforward and potentially suitable for self service.

the current manual tools and workarounds
- 20-year-old collections database.
- Multiple spreadsheet trackers.
- Email trails and templates.
- Local processes/workarounds built by individual teams.
- Agents manually reconcile information between different sources.
- Agents manually track promises to pay.
- Process relies heavily on individual memory and manual updates.
- Agents have memorised workarounds to work effectively
- Different teams use their own approaches.
- Agents need to check multiple spreadsheets to establish previous customer contact/activity.

the operational symptoms
- Missed follow-ups.
- Duplicate activity/contact.
- Inconsistent status updates.
- Cases can remain in pending callback without callback ever being completed.
- Follow ups can be lost during handoff between shifts
- Agents can't easily identify when other agents have contacted a customer
- Agents spend time searching for information rather than contacting customers.
- No consistent definition of what each case status means.

the financial consequences
- direct effect on debt recoveries
- Delayed actions and inconsistent follow-up contributing to est 15% revenue loss.
- Manual work consumes agent capacity, creating an operational cost.
- straightforward cases currently take ~18 mins to handle, when they should be 10 minutes, using up more capacity.
- poor quality data makes it difficult to accurately quantify lost revenue.

the main stakeholder priorities/tensions
Priorities:
- Amina wants to see exactly where current processes create missed follow-ups, duplicate effort and wasted handling time.
- Daniel wants transparent assumptions, sensitivity testing and a value case to provide evidence for financial growth.
- Gareth wants the process to be streamlined for easy use by agents.
- Priya wants the whole process well thought out and fully documented, for easy delivery.

Tensions:
- Daniel may favour automation that produces measurable financial returns, while Amina may value changes that save agent time even if they don't immediately produce hard financial savings.
- Daniel wants a strong financial case for automation. Gareth won't support automation if complex cases simply get pushed back onto agents, even if the model suggests savings.
- Gareth wants processes to be simple and practical for agents, meaning automation needs to reduce workload rather than introduce additional systems, complexity or manual exceptions.
- There may be pressure to implement improvements quickly to realise operational and financial benefits, while Priya requires the redesigned process to be properly documented, controlled and deliverable.
